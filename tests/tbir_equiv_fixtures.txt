# TB-IR equivalence-fixture registry — consumed by tests/run_tbir_equiv.sh
# and tests/run_arch_dut_fixtures.sh (single source of truth for the
# equivalence matrix; do not duplicate these rows in scripts).
#
# Each row names a fixture that must behave IDENTICALLY under BOTH C++
# emitters (`harc sim --codegen v1` and `--codegen tbir`): same verdict,
# and zero `harc trace-diff` divergences between the semantic traces.
#
# Format (pipe-separated, one row per fixture — schema v2):
#
#     test_name | top | sv_files | arch_dut | expect
#
#   test_name  HARC fixture stem — tests/fixtures/<test_name>.harc
#   top        SV top-module name, passed via --top
#   sv_files   space-separated DUT files relative to tests/dut/
#   arch_dut   ARCH DUT source relative to tests/dut/ for the optional
#              ARCH-native sweep (`harc sim --dut`, needs ARCH_BIN), or
#              `-` when no proven .arch sibling exists (sweep skips row)
#   expect     `pass` — both codegens must print ALL TESTS PASSED;
#              `fail` — both codegens must exit nonzero WITHOUT printing
#              ALL TESTS PASSED (deliberate-failure fixtures, e.g. the
#              log(fatal, ...) path). Either way the two traces must
#              trace-diff clean: the failure must be recorded identically.
#
# Lines starting with '#' and blank lines are ignored.
#
# This file is APPEND-ONLY: each PR that brings a fixture into the TB-IR
# subset (covergroups, helpers, wait-until, ...) adds its rows here in the
# same PR. Merge conflicts resolve as the line union of both sides. Do not
# add rows for constructs your PR does not enable — the harness fails the
# whole run if any listed fixture does not behave as its `expect` column
# specifies under `--codegen tbir`.
